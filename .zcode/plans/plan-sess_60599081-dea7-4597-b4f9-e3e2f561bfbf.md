## 目标
系统性改善应用的即时交互反馈：所有常规按钮提供轻微“按下缩放/下沉”反馈和一致的禁用态；主要业务操作提供清晰的进行中、成功与失败反馈，同时保持现有深浅主题、无障碍焦点样式和现有业务行为不变。

## 实施步骤

1. **统一基础按钮交互样式**
   - 修改 `src/index.css` 的 `.btn` 基类：
     - 保留现有颜色过渡、间距和焦点可见轮廓。
     - 增加 `cursor-pointer`、统一的 disabled 视觉（降低透明度、`cursor-not-allowed`、禁止 pointer interaction），避免禁用按钮仍显示 hover/pressed 状态。
     - 增加 `transform` 过渡以及 `:active` 的轻微 `scale(0.98)` 与 `translateY(1px)`，形成短促的按压反馈；不改变布局尺寸。
     - 让 `.btn-primary`、`.btn-secondary`、`.btn-ghost`、`.btn-danger` 继承同一套行为，并确保 hover/active/disabled 状态层级清晰。
   - 对非 `.btn` 的高频小按钮（例如提交前缀 chip、历史菜单项、Toast 关闭按钮、行尾图标按钮）统一补上必要的 pressed/disabled/focus 反馈，避免只改共享类后仍有明显“无反馈”孤岛。
   - 加入 `prefers-reduced-motion` 下的降级规则，保留颜色/状态变化但关闭位移缩放动画。

2. **补齐通用可访问交互语义**
   - 对已有 loading 按钮在不改变可访问名称的前提下补充 `aria-busy`（仅异步进行中时为 true），并确保 Spinner 作为装饰图标处理。
   - 检查仅图标按钮的 `aria-label`、键盘 focus 样式，特别关注 `ChatView` 中目前只在 hover 显示的复制按钮，以及 `ContextMenu` 菜单项的键盘聚焦背景。
   - Toast 保持现有 `role="status"` 的成功/普通信息行为；错误 Toast 改为更适合立即告警的语义（或通过 `aria-live` 分区处理），并为关闭按钮使用统一的可见 pressed/focus 反馈。

3. **审查并补齐主要业务操作反馈**
   - 以 `CommitPanel.tsx` 的现有模式为基准，逐项审查并只在缺失处补充：
     - Git 提交、提交并推送、推送、拉取、暂存/取消暂存。
     - 分支创建/切换/删除、历史 checkout/revert/cherry-pick/reset。
     - stash、tag、submodule、merge/rebase、diff 行级暂存/丢弃。
     - 仓库打开/刷新、代码审查、AI 生成、聊天发送、设置保存和复制。
   - 对耗时操作统一保证：点击后立即禁用相关按钮防止重复触发、显示 Spinner 或进行中文案、Promise 结束后恢复状态。
   - 对关键操作沿用现有 `toastStore` 与 `formatError`：成功显示简洁 Toast，失败显示错误 Toast；已有长错误内联区域继续保留，不重复制造噪音。
   - 高频且瞬时的操作（如复制、选择前缀、切换选项）优先采用就地状态变化；关键 Git/AI 结果采用 Toast，遵循用户选择的“平衡反馈”密度。
   - 不重写现有 store/Tauri 调用链，优先复用已有 loading 字段、Toast 和错误处理，避免引入新的全局状态架构。

4. **增加回归测试**
   - 新增针对基础按钮类名/disabled 行为的轻量组件或 DOM 测试，确保共享按钮具备按压、禁用约定（CSS 真实渲染仍由构建验证）。
   - 以现有 `src/pages/ChangesView.test.tsx` 的 mock 模式为模板，为至少一个核心异步流程（优先 `CommitPanel`）覆盖：点击后禁用、Spinner/处理中案、成功 Toast、失败 Toast、完成后恢复以及 busy 时不重复调用。
   - 为补过的短暂复制反馈和 Toaster 语义补充必要测试；不为纯 CSS 变体制造脆弱的视觉快照。

5. **验证与回顾**
   - 运行现有 Vitest 全量测试。
   - 运行 `npm run build`，确认 Tailwind `@apply`、TypeScript 和 Vite 构建均通过。
   - 检查 git diff，确保只涉及前端交互/反馈相关文件，不覆盖用户已有的 `src-tauri/capabilities/default.json` 未提交修改。
   - 若测试或构建失败，按实际输出修复或明确报告，不宣称未验证的桌面 WebView 视觉效果；最终说明哪些反馈已统一、哪些业务流程沿用已有机制。
