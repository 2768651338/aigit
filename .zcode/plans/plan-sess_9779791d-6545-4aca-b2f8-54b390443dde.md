# “全部三阶段”实施计划

目标是把上一轮提出的三阶段拓展全部落地：快速收益、中期 Git/AI 能力、长期 AI 差异化能力，同时补齐凭据安全、错误处理、测试、CI、发布和文档。由于范围很大，将按可独立验证的里程碑推进；每个里程碑都先实现底层契约，再接入 UI，最后运行对应测试。

## 0. 统一基础设施与约束（所有后续功能的前置）

### 0.1 Git CLI 执行层
- 从 `src-tauri/src/git/merge.rs` 抽取公共 Git CLI runner。
- 统一工作目录、环境变量、超时、stdout/stderr、退出码和可取消任务。
- 对用户输入统一使用参数数组，不拼 shell 字符串；对 remote、branch、path、URL 做长度和格式校验。
- 统一从 Git 的结构化状态（例如 `git diff --name-only --diff-filter=U`、config 输出）读取结果，避免依赖本地化人类可读输出。

### 0.2 结构化错误协议
- 扩展 `src-tauri/src/error.rs` 返回稳定 `code`、`message`、`retryable`、可选诊断 ID。
- AI HTTP 错误按认证失败、权限、限流、超时、网络、上游 5xx、解析失败分类。
- 限制并脱敏上游响应正文，生产环境不向 UI 暴露完整堆栈。
- 前端 `formatError`、Toast、ErrorBoundary 和各 Store 改为按错误码显示可操作提示。

### 0.3 配置与凭据安全
- 新增 Windows Credential Manager/系统 keyring 适配层。
- TOML 仅保存非敏感设置和凭据存在标记；新增独立的 set/delete key 命令。
- `get_config` 不再返回明文 API Key；AI command 不再从前端接收包含 Key 的完整配置，而由后端加载配置和凭据。
- 兼容旧版本：首次读取旧 TOML 时迁移 Key，只有凭据成功写入后才删除明文；失败保留原文件并提示。
- 配置保存采用临时文件、flush/sync、rename 的原子写入，并处理损坏配置备份/恢复。
- 自定义 Base URL 明确提示 Key 将发送到该端点；为请求统一增加连接/总超时、响应体上限和共享 reqwest Client。

### 0.4 状态模型整理
- 保持 `repoStore` 按绝对路径隔离，但内部拆分 changes、branches、remote、operations 等领域 slice。
- 将 AI 全局 `loading` 改为按仓库 + 操作类型 + requestId 的任务状态，为流式响应和并发打基础。
- 将 merge/rebase 状态升级为可扩展 operation union，保留旧 UI 所需的兼容选择器。

## 1. 第一阶段：快速收益与现有能力产品化

### 1.1 行级/代码块暂存
涉及：`ChangesView.tsx`、`DiffViewer.tsx`、`repoStore.ts`、`commit.rs`、i18n。
- 将工作区 diff 和暂存区 diff 分开渲染，不再混合传给默认只读 DiffViewer。
- 工作区使用 `mode="workdir"`，暂存区使用 `mode="staged"`，提供块级、行级暂存/取消暂存。
- 修正 rename 使用 `old_path`、无换行、删除/新文件等 patch 场景；临时 patch 文件改为唯一安全临时文件并保证清理。
- 操作前校验目标 diff 未变化，操作后按仓库路径刷新状态并保留选中文件。
- 增加 patch 构造、hunk/line 选择、Rust apply 失败和临时文件清理测试。

### 1.2 克隆/初始化仓库
涉及：`TabBar.tsx`、空状态、repoStore、git service、Rust repo command、新建仓库对话框。
- “+”和空状态提供“打开本地仓库 / 克隆远程仓库 / 初始化仓库”。
- 克隆表单包含 URL、目标目录、目标存在校验、loading、错误和完成后自动打开新 Tab；第一版明确支持公开 HTTPS，并为认证失败给出提示。
- 初始化选择目录后执行 init 并自动打开。
- 长耗时操作使用异步任务状态；后续接入统一进度/取消接口。
- 增加表单校验、成功打开和失败路径测试。

### 1.3 Amend 与提交工作流
涉及：`commit.rs`、`git_cmd.rs`、`git service`、`repoStore`、`CommitPanel.tsx`。
- 扩展 amend 为“将当前暂存内容与现有 HEAD 合并提交”，同时支持仅修改提交信息。
- 提交面板增加 Amend 模式、已推送历史警告和明确确认；不自动 force push。
- 统一普通 commit 与 amend 的 signature fallback 行为。
- 禁止智能拆分模式复用普通提交的隐式 `stageAll()`。
- 增加临时 Git 仓库测试，验证 message-only、staged changes、空 index 和已推送警告逻辑。

### 1.4 Diff 布局设置
涉及：`SettingsView.tsx`、`ChangesView.tsx`、设置 Store/类型和测试。
- `show_diff_inline=true` 时保持当前右侧内联 Diff。
- 关闭时进入独立全宽 Diff 视图，提供返回文件列表/关闭 Diff 操作，而不是静默丢失查看能力。
- 仓库切换和文件选择时同步布局状态。

### 1.5 Chat 跨仓库隔离
涉及：`ChatView.tsx`、`aiStore.ts`、测试。
- 文件列表改为按 repo path 缓存，或在仓库切换时可靠清理 files/filesLoaded/filesLoading。
- 加载响应返回时校验请求对应的 repo path，防止旧请求覆盖新仓库。
- AI loading 改为每仓库/操作隔离。
- 增加仓库切换、异步竞态和附件列表隔离测试。

### 1.6 洞察真实时间范围与国际化
涉及：`insights.rs`、Insight DTO、`InsightsView.tsx`、`insights.ts`、`ReportGenerator.tsx`、导出工具和 locale。
- 后端支持起止日期参数，在聚合前过滤 CommitRecord，返回区间内提交数、贡献者、趋势和主要提交。
- UI 增加 7/30/90 天、全部和自定义范围，导出报告写明统计区间。
- 修复“最近一周”使用全历史统计的问题；明确本地时区日期边界。
- 拆分本地分支与远端跟踪分支统计。
- 将洞察新增硬编码文本全部迁移至中英文 locale。
- 增加日期边界、时区、作者统计和报告模板测试。

### 1.7 第一阶段验证门
- 前端：单元测试、类型检查、生产构建。
- Rust：fmt、clippy、cargo test。
- 使用临时 Git 仓库手动验证：打开、init、clone、行级暂存、amend、洞察筛选。

## 2. 第二阶段：完整 Git 工作流

### 2.1 Remote / Fetch / Upstream 管理
涉及公共 Git CLI、remote 模块、命令注册、service、repoStore、BranchesView、新 RemotePanel。
- 增加 RemoteInfo、TrackingInfo 模型和 list/add/edit/remove/rename/set-url 命令。
- 增加 fetch、fetch --prune、fetch tags，并把 Fetch 与 Pull 分成独立操作。
- push/pull 默认使用当前分支真实 upstream；无 upstream 时只在用户确认后 set-upstream，不强制 origin。
- 远程分支支持创建本地 tracking branch；tag 支持远端推送和删除。
- ahead/behind 在 fetch 后刷新，显示数据更新时间。
- 使用参数数组和白名单校验，避免 remote/branch 输入进入 shell。
- 增加多 remote、非 origin、upstream、fetch 错误和 URL 解析测试。

### 2.2 三方冲突解决器
涉及 operation 状态、merge 模块、冲突命令、`MergeRebaseBar.tsx`、新 ConflictResolver。
- 统一 merge/rebase/cherry-pick/revert 的 operation state。
- 从 index stage 获取冲突文件及 BASE/OURS/THEIRS blob 内容，不解析本地化 CLI 文本。
- 第一版限定文本文件，提供三栏内容、逐块 ours/theirs/both、可编辑合并结果、保存并 stage、标记解决、Continue/Abort/Skip。
- 二进制、rename/delete、submodule 冲突提供外部编辑器回退。
- 支持 stash apply/pop 冲突接入同一界面。
- 增加冲突夹具和临时仓库集成测试。

## 3. 第二阶段：AI 交互升级

### 3.1 AI 流式响应、取消和并发
涉及 AI provider trait、OpenAI/Claude/Ollama、`ai_cmd.rs`、Tauri event/channel、`ai.ts`、`aiStore`、Chat/Review/CommitPanel。
- 将 provider 请求抽象为统一 requestId + Started/Delta/Usage/Completed/Cancelled/Failed 事件。
- 使用 reqwest stream 解析 SSE/JSONL，兼容不支持流式的 fallback。
- 为每个请求注册 cancellation token/abort handle，增加 cancel command。
- 前端按 repo、操作类型、requestId 更新增量文本，切换仓库不串状态。
- 加入请求超时、最大响应限制、重试策略和用户可见停止按钮。
- 通过 mock HTTP server 测试各 provider 的 chunk 解析、断流、错误、取消竞争。

### 3.2 结构化 AI 审查
涉及审查类型、AI command/service/store、ReviewView、ChangesView 定位状态。
- 定义 ReviewReport/ReviewFinding，包含 severity、category、file、行范围、说明、建议、置信度和元数据。
- provider 支持结构化输出时启用 schema；其他 provider 使用严格 JSON prompt + serde 校验 + 有限 repair retry。
- 解析失败保留 raw response，但主 UI 回退到安全 Markdown，不把任意字符串当可信结构。
- UI 提供严重程度筛选、文件分组、跳转到改动行、已处理/误报状态、复制建议和 Markdown 导出。
- 为工作区快照/head hash 建立报告关联，改动变化时提示报告过期。

### 3.3 对话持久化和上下文控制
- 按 repo 保存会话、标题、附件元数据和最近消息；提供删除和“本地不保存”开关。
- 显示估算 token/context 大小，对大文件和大 patch 提示并允许确认。
- 自动截断或摘要旧消息；敏感附件默认不自动上传。
- 所有本地会话数据与凭据分离，提供清空数据入口。

## 4. 第二阶段：安全与质量基础

### 4.1 凭据和敏感数据
- 完成 Windows Credential Manager 迁移、get_config 脱敏和 AI 后端加载。
- 增加“测试连接”、Ollama 模型探测和自定义端点风险提示。
- 限制日志、错误正文、导出报告中的 Key、Authorization、cookie、环境变量和源码秘密。

### 4.2 测试补齐
- 配置迁移/损坏恢复/原子保存测试。
- AI provider mock HTTP 契约测试。
- repoStore 多 Tab 竞态测试。
- Git remote/merge/rebase/patch 临时仓库集成测试。
- 结构化审查 schema、失败回退、跨页定位测试。
- 逐步加入覆盖率报告与最低阈值。

## 5. 第三阶段：AI 差异化能力

### 5.1 AI 智能拆分提交
涉及 CommitPlan 类型、AI command、patch 选择、repoStore、CommitPlan UI。
- AI 只生成建议计划，不直接执行。
- 计划绑定 repo path、HEAD、index tree 和 diff hash；工作区变化后失效。
- 每组展示文件/hunk、理由和 Conventional Commit message。
- 用户逐组预览、确认、stage、commit；每一步可取消、失败可恢复。
- 处理已有 staged changes，禁止隐式 stage-all；不支持安全拆分的 binary/复杂 rename 明确回退。
- 增加重复 hunk、patch 失败、中途提交失败和恢复测试。

### 5.2 本地代码全文 + 向量索引
用户已选择第一版同步做向量索引，因此按“全文/符号检索 + 可选本地/云 embedding”设计。
- 新增按 repo 的索引任务和状态：扫描 tracked files，遵守 `.gitignore` 与额外排除规则，过滤二进制、超大文件、`.env`、证书和明显秘密。
- 以 blob OID/文件哈希/模型版本作为增量索引键；索引与当前 HEAD/worktree 版本绑定。
- 先实现分块、语言/符号元数据和本地全文索引，再加入 embedding provider 与向量存储；支持 Ollama 本地 embedding 和用户明确启用的云 embedding。
- 查询返回 top-k chunk、文件、行范围和来源，Chat 显示引用并将筛选结果注入上下文。
- 增加重建、暂停、删除索引、排除规则和“永不上传索引”设置。
- 控制 token、并发、磁盘和 CPU；索引任务可取消。
- 增加秘密过滤、增量更新、模型切换和引用准确性测试。

### 5.3 GitHub PR 工作流
用户已选择 GitHub。
- 第一版解析 GitHub remote，支持 compare/create URL，避免不必要的 token。
- 第二版复用 `gh` CLI（若存在）完成 PR list/view/create、Draft PR、checkout 和 checks；检测认证状态并给出安装/登录提示。
- 第三版提供原生 GitHub API 适配，使用已完成的 Credential Manager 保存 token，支持 enterprise base URL、分页、限流和权限错误。
- 从提交范围和结构化审查生成 PR 标题/描述；本地审查默认不自动发布评论。
- 后续支持把结构化 finding 映射为 inline review comment，但必须要求用户逐条确认。
- 增加 remote URL 解析、gh 不存在、权限、限流和 PR 创建失败测试。

## 6. 发布、CI、文档与元数据

### 6.1 CI 门禁
新增 GitHub Actions，在 Windows runner 执行：
- `npm ci`
- 前端测试、类型检查、生产构建
- `cargo fmt --check`
- `cargo clippy --all-targets -- -D warnings`
- `cargo test`、`cargo check`
- npm/Cargo 依赖审计
- 构建产物和许可证一致性检查

### 6.2 发布和自动更新
- 统一 package/Cargo/Tauri/UI 版本来源或增加版本一致性校验。
- tag 驱动 Windows MSI/NSIS 构建、校验和、Release notes 和签名。
- 接入 Tauri updater；更新清单和安装包使用签名校验，失败时保留旧版本。
- 先在隔离 Windows 环境验证安装、升级、失败恢复，再开放自动更新。

### 6.3 元数据和文档
- 将 npm/Cargo 许可证元数据统一为 Apache-2.0。
- 修复 README 版本、TOML 示例、主题描述和目录结构。
- 增加 CHANGELOG、CONTRIBUTING、SECURITY、隐私/数据发送说明、故障排查和发布说明。
- 文档明确 API Key 存储位置、云端发送边界、索引隐私策略、测试命令和支持平台。

### 6.4 Tauri 安全边界
- 审核并收紧 `capabilities/default.json` 的 FS 权限和路径 scope。
- 在验证 Markdown、外链和导出流程后启用最小可用 CSP。
- 对文件路径、外部 URL、导出目标和自定义 AI endpoint 做白名单/格式/长度校验。

## 7. 每个里程碑的完成标准

1. 功能从 UI → Store → Service → Tauri command → Git/AI 模块完整贯通。
2. 有对应单元测试；涉及 Git/网络/凭据的功能有隔离集成或 mock 测试。
3. 前端测试、类型检查、构建和 Rust fmt/clippy/test 通过。
4. 不引入 shell 拼接、明文凭据、未限制的错误正文、未校验的路径或 URL。
5. 更新 i18n、README 和版本/配置契约。
6. 在继续下一里程碑前检查 `git diff`、`git status` 和实际测试输出。

## 8. 实施顺序与交付方式

按以下顺序连续推进：

1. 基础错误/配置/凭据/CLI 执行器与测试基础。
2. 第一阶段快速收益。
3. Remote 与冲突解决。
4. AI streaming/取消、结构化审查、对话持久化。
5. 安全与质量补强。
6. 智能拆分提交。
7. 全文 + 向量代码索引。
8. GitHub PR 工作流。
9. CI、发布、自动更新、文档和安全边界收尾。

在每个阶段结束时汇报：已完成文件/功能、实际测试结果、未完成项和下一阶段入口；不把“计划完成”当作实现完成。
